# png-glitch CLI Visual Guide

This guide showcases every command-line option available in `png-glitch`, using `crates/png-glitch/etc/sample00.png` as the base image for comparison.

Every image was made with `--seed 42`, so you can reproduce it with the command shown plus `--seed 42`. All images are generated by [`examples/gen_gallery.rs`](../examples/gen_gallery.rs); regenerate them with:

```zsh
cargo run --release --example gen_gallery
```

> **Why do color effects look like noise on PNG?** Effects edit the *filtered* scan-line bytes, not decoded pixels (see the [Developer Guide](../DEVELOPER_GUIDE.md)). The decoder then reconstructs each pixel from its neighbours, so a small change spreads into streaks, gradients and noise; that is the glitch. Put `remove-filter` first to make the effects act on the real colors instead (see [Recipes](#6-recipes)).

## 1. Color Manipulation

### Invert
Inverts all color channels.
`--invert`
![Invert](./gallery/invert.png)

### Brighten
Increases brightness.
`--brighten 20000`
![Brighten](./gallery/brighten.png)

### Darken
Decreases brightness.
`--darken 40`
![Darken](./gallery/darken.png)

### Color Distortion
Adds random noise to each color channel.
`--color-distortion 0.1 --color-distortion-strength 50`
![Color Distortion](./gallery/color_distortion.png)

### Color Space Glitch (HSL)
Manipulates Hue, Saturation, and Lightness.
`--color-space-glitch 0.2 --hue-shift 120 --saturation-mult 1.5`
![Color Space Glitch](./gallery/color_space_glitch.png)

### Chromatic Aberration
Spatially shifts color channels to create fringes.
`--chromatic-aberration 0.3 --r-offset 10 --b-offset 10`
![Chromatic Aberration](./gallery/chromatic_aberration.png)

### Shift Channels
Swaps or offsets channel values directly.
`--shift-channels 10000,20000,-10000`
![Shift Channels](./gallery/shift_channels.png)

### Channel Swap
Swaps two color channels.
`-f 'channel-swap:magnitude=0.3,target=rg'`
![Channel Swap](./gallery/channel_swap.png)

## 4. PNG Filter Abuse

These options force the PNG decoder to misinterpret pixels by manipulating internal filter types.

### Set Filter Type (tag only) and Regenerate (recompute)
Two different operations:

- `-f set-filter-type=paeth` overwrites the filter-type tag of every row and leaves the filtered bytes as they are, so the decoder misreads them.
- `-f regenerate=paeth` recomputes every filtered value (a new generation); the image looks the same but its bytes change. Also `regenerate=adaptive` and `regenerate=sub,up,paeth` (row `i` uses `pattern[i % len]`).

`--remove-filter`, `--sub`, `--up`, `--average` and `--paeth` are **deprecated** aliases of `regenerate=<type>` (same output; they print a warning to stderr).

### Remove Filter (deprecated, use `-f regenerate=none`)
Re-encodes every scanline with filter type `None`. The image looks unchanged, but the bytes underneath are now raw pixels, which changes what later effects do.
`--remove-filter`
![Remove Filter](./gallery/remove_filter.png)

## 5. WebP Effects

These use `crates/webp-glitch/etc/sample00.webp` as the input.

![Original WebP](../crates/webp-glitch/etc/sample00.webp)

### Macroblock Glitch
Swaps, duplicates or zeroes 16x16 VP8 macroblocks.
`--macroblock-glitch 0.15`
![Macroblock Glitch](./gallery/webp/macroblock_glitch.webp)

### Lossy Artifact
Re-encodes through lossy VP8 at a very low quality.
`--lossy-quality 5`
![Lossy Artifact](./gallery/webp/lossy_artifact.webp)

### Pixel Sort (WebP)
Effects shared with PNG work on decoded pixels for WebP, so they do not turn into noise.
`--pixel-sort 0.3`
![Pixel Sort on WebP](./gallery/webp/pixel_sort.webp)

`--alpha-glitch` only affects images with an alpha channel, so it has no example here (the sample WebP has none).

## 6. Recipes

A recipe is a YAML list of filters, applied in order. The files are in [`gallery/recipes`](./gallery/recipes); each image is exactly the output of:

```zsh
png-glitch crates/png-glitch/etc/sample00.png --config docs/gallery/recipes/<name>.yaml --seed 42
```

(`webp-blocks` uses `crates/webp-glitch/etc/sample00.webp` instead.)

### Filtered vs. unfiltered

The same effect, without and with `remove-filter` first.

| `pixel-sort` only | [`clean-pixel-sort.yaml`](./gallery/recipes/clean-pixel-sort.yaml) |
| :---: | :---: |
| ![Pixel sort on filtered bytes](./gallery/pixel_sort.png) | ![Pixel sort after remove-filter](./gallery/recipes/clean-pixel-sort.png) |
| **`darken` only** | **[`clean-darken.yaml`](./gallery/recipes/clean-darken.yaml)** |
| ![Darken on filtered bytes](./gallery/darken.png) | ![Darken after remove-filter](./gallery/recipes/clean-darken.png) |

### VHS Tracking
[`vhs-tracking.yaml`](./gallery/recipes/vhs-tracking.yaml)
```yaml
filters:
  - type: remove-filter
  - type: horizontal-shift
    magnitude: 0.05
  - type: chromatic-aberration
    magnitude: 0.4
    r_offset: 6
    b_offset: -6
  - type: color-distortion
    magnitude: 0.15
    strength: 40
```
![VHS Tracking](./gallery/recipes/vhs-tracking.png)

### Filter Corruption
[`filter-corruption.yaml`](./gallery/recipes/filter-corruption.yaml)
```yaml
filters:
  - type: sub-filter
  - type: change-filter-type
    magnitude: 0.2
  - type: replace
    magnitude: 0.01
```
![Filter Corruption](./gallery/recipes/filter-corruption.png)

### Hue Melt
[`hue-melt.yaml`](./gallery/recipes/hue-melt.yaml)
```yaml

  - type: remove-filter
  - type: pixel-sort
    magnitude: 0.4
    criterion: hue

    magnitude: 0.3
    hue_shift: 60.0
```

## 7. Advanced Usage

### Batch Processing
Process all PNGs in a directory in parallel:
```zsh
png-glitch ./input_dir --batch-output ./output_dir --invert --block-scramble 0.05
```

### Reproducible Seeds
Use `--seed <N>` to get the same result every time.

### Configuration Files (YAML)
Combine multiple filters into a pipeline:
```yaml
filters:
  - type: RemoveFilter
  - type: BlockScramble
    magnitude: 0.1
  - type: ChromaticAberration
    magnitude: 0.2
    r_offset: 5
  - type: ColorSpaceGlitch
    magnitude: 0.1
    hue_shift: 180.0
```
Run with: `png-glitch input.png --config config.yaml`
